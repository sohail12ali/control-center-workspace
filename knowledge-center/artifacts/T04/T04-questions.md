|---|----------|--------|-------|-------|----------|
| Q1 | Which hadith collections should be included in v1? Options: (a) Nawawi 40 + Hadith Qudsi only (~300 KB, zero search infrastructure needed), (b) Nawawi 40 + Hadith Qudsi + Bukhari + Muslim (~8-12 MB SQLite), (c) All six Kutub as-Sitta (~15 MB SQLite), (d) All 10 fawazahmed0 collections (~20 MB SQLite). | resolved | CLARIFY | anjum@hu-manity.co | **All 10 fawazahmed0 collections** bundled in v1. No size constraint. |
| Q2 | What is the maximum acceptable bundled asset size increase for the hadith feature? The Quran is already 7.3 MB. A full Kutub as-Sitta bundle adds ~10-15 MB. | resolved | CLARIFY | anjum@hu-manity.co | **No size constraint.** Full corpus acceptable regardless of asset footprint. |
| Q3 | What search experience is required? (a) Full-text keyword search (requires SQLite FTS5 DB), (b) Browse only — collection → book → hadith number, (c) Both search and browse, (d) Numbered reference lookup (e.g. "Bukhari 6224"). | resolved | CLARIFY | anjum@hu-manity.co | **All three modes:** full-text keyword search + browse (collection → book → hadith) + numbered reference lookup. |
| Q4 | What languages must be supported in v1? The app supports en/ar/ur/hi. The fawazahmed0 corpus covers en, ar, ur but NOT Hindi. Should Hindi support be deferred, or is it a v1 blocker? | resolved | CLARIFY | anjum@hu-manity.co | **Hindi deferred** to a future ticket. v1 supports en, ar, ur. |
| Q5 | Where should hadith live in the UI? Options: (a) New card in Tools grid (no nav-bar change), (b) Upgrade the Dua tab to "Dua & Hadith" (combined screen), (c) New fifth bottom nav item replacing one existing tab, (d) Accessible from Dashboard widget/card only. | resolved | CLARIFY | anjum@hu-manity.co | **Create a new "Books" tab.** Quran, Hadith, and Duas are consolidated under one Books nav tab. This is a navigation refactor — existing Quran tab and Duas section merge with new Hadith into a single Books destination. |
| Q6 | Is offline-first mandatory, or is a network-backed search (Dorar.net API, free, Arabic FTS) acceptable as a supplement or primary mode? Network mode gives much better Arabic morphological search but breaks in airplane mode. | resolved | CLARIFY | anjum@hu-manity.co | **Offline-first mandatory.** No network dependency for hadith. SQLite FTS5 bundle is the sole source. |
| Q7 | Should the feature display hadith grade (Sahih / Hasan / Daif)? The fawazahmed0 corpus includes grade metadata. | Q8 | Is a "Hadith of the Day" daily card on the dashboard in scope for v1, or deferred? (Similar to existing Ayah of the Day card pattern.) | resolved | CLARIFY | anjum@hu-manity.co | **Deferred.** No Dashboard changes in v1. Hadith of the Day is out of scope. |
| Q9 | The fawazahmed0 corpus is Unlicense (public domain). Is the team comfortable using this source, or is a different licensed corpus required (e.g. sunnah.com which requires an API key and has licensing restrictions)? | resolved | CLARIFY | anjum@hu-manity.co | **Approved.** fawazahmed0 Unlicense corpus is acceptable. |

| Q11 | How should the Hadith screen surface the three search modes (FR-05 FTS, FR-06 browse, FR-07 numbered lookup) in the UI? | Q13 | NFR-03 requires a SHA-256 checksum for the bundled SQLite DB. Where should the expected checksum live? | Q15 | How should the hadith build script source the fawazahmed0 JSON files?
