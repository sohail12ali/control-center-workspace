# Analysis: T-037

## Context

User request (2026-10-05): a more responsive, VS Code-like console: expandable sections, easy layout changes, draggable pane borders. Decisions already taken ([[T-037-summary]]): splitters on all four surfaces (Agents panes, Vault panes, ticket detail as a docked resizable panel, board lane width), built alongside [[T-031-summary]]. This analysis re-verifies every lead in the summary against the code (2026-10-05, branch `development`) and records what later stages must respect. It is descriptive; nothing here is a requirement until `requirements draft`. Rendering and drag behaviour are **[BROWSER] not verified** throughout: no browser tool was available, only source reading, `grep`, and `pytest`.

**Preference store.** `C.prefs` (`core.js:444-458`): synchronous `get(key,fallback)`, `set(key,val)`, `del(key)` over `localStorage["console."+key]`, `get` re-parses JSON on every call. At analysis time `core.js` is **unmodified** in git, so T-036 has not landed.

**Re-render model.** `go()` (`app.js:124-154`) closes the drawer (`:128`), calls the previous tab's `onLeave` (`:131`), clears `#view` (`:141`), resets `host.className` (`:147`) and calls `impl.render`. `go(state.active)` is also run by the `r` key (`:291`) and the refresh button (`:299-300`). Board `paint()` rebuilds the whole board DOM on every search keystroke, "Show more" and move (`board.js:245-290,555`). So no pane size may live in tab DOM; it must come from prefs (or a CSS variable on an element that is never re-rendered) every time a surface is built.

## Key Findings

Verdicts on the summary's leads (CONFIRMED / CORRECTED / REFUTED), then new findings.

### Summary leads

- **L1 "no splitters, pointer-drag code or resize cursors anywhere": CONFIRMED for splitters, CORRECTED for drag code.** Unrelated mouse/DnD drag code exists (see Current State). Significance: the Vault canvas listens for `mousemove`/`mousedown` on `#vaultFx` (`vault.js:392,419`) and `mouseup` on `window` (`:426`); a splitter handle must live outside `.vault-stage` (which is `overflow:hidden`, `styles.css:1634`) and use Pointer Events.
- **L1b "every pane width is a fixed CSS value": CORRECTED.** The Agents list is fluid (`clamp(208px,22vw,302px)`, `styles.css:841`); the rest are fixed. A stored absolute pixel width would stop tracking the viewport, so clamping is needed (see Research and finding N6).
- **L2 Agents geometry: CONFIRMED** (`styles.css:839-843`, `:938-941`; fold state `chatListHidden` at `agents.js:132,1498,1503`).
- **L3 Vault geometry: CONFIRMED** (`styles.css:1576-1591`; viewer opens by adding `.has-viewer`, `vault.js:495`).

- **L5 board lane width: CONFIRMED** (`--lane-w` `styles.css:78`, `.lane` `:689`), with two overrides the summary did not name: the 1280 px trim `:1982-1984` and the 720 px rule that bypasses the variable `:2056`.
- **L6 "collapse primitive used only on Settings today": CONFIRMED.** `C.panel(..., {collapse})` is `core.js:204-221` and `collapsible()` is `:259-298` (summary cited only the latter); 13 panel ids and 7 `C.group` ids, all `set.*` in `settings.js` (`:90-1908`, groups `:1376-1481`). - **N2 Overview "Needs attention" key handler would fire from a collapse header.** `overview.js:303-317` makes the panel focusable and handles `Enter` on any descendant (`rows[idx].click()`, `:312`) without checking `e.target`; `collapsible()` makes the header `role=button` and toggles on Enter/Space (`core.js:288-292`). Enter on that header would toggle **and** navigate to a board. Needs a target guard when adding `ov.attention`.
- **N3 Overview onboarding card already folds itself** (`onboardingOpen` pref and a "Hide steps" button, `overview.js:50,87-102`) and is dismissible (`hideOnboarding`, `:104-107`). A second fold would duplicate it. Its title also changes ("Getting started" / "Setup complete", `:110`), so it needs a stable id.
- **N4 Agents right rail is rebuilt on every `meta` event.** `paintRail2` (`agents.js:1169-1240`) runs from `st.repaintChat` (`:970-976`); its sections are raw `<section class="ct-panel"><h4>` (`:1165,1177,1192,1205,1224`), not `C.panel`/`C.group`, and `.ct-split` itself is recreated per chat in `mountChat` (`:960`). - **N5 Vault `resize()` is heavy for a drag.** The `ResizeObserver` on `#vaultStage` (`vault.js:450-452`) calls `resize()` per layout change; it reallocates both canvas backing stores and redraws the whole graph (`:233-252`). A live drag would do that every frame. The `setTimeout(resize, 60)` calls (`:507,515,530`) predate the observer and are now redundant. Perf not measured.
- **N6 Inline custom property beats a media-query `:root` value.** `--vault-side` and `--lane-w` are set on `:root` and trimmed in media queries (`styles.css:1983`, `:2024`). A value written inline on `<html>` would override those trims at every width; one written on the pane container affects only that container. For `.appshell`, do **not** inline `grid-template-columns` (it would beat the `<=900px` `1fr` at `:2006`); consume a variable inside the existing rule instead. Hence also: switch stored sizes off at `<=900px` in step with the CSS.
- **N7 Docking moves the page, not just the panel.** Today `.drawer` is `position:fixed; top:0; bottom:0` at `z-index:41` and `.scrim` is `position:fixed; inset:0` at `z-index:40` (`styles.css:1673-1685`), above `.topbar` (`z-index:20`, `:284`). Content impact: `main#view` (`index.html:41`, `styles.css:403`) is the only container that can shrink; the board's `.lanes` scrolls horizontally (`styles.css:685`). Computed from CSS only: the tickets board has 5 lanes (`console/config/boards/tickets.toml`, `done` terminal so 52 px cold) which need about 1136 px at 1280 and 1208 px at 1400; a 430 px dock leaves 850 and 970 px, so roughly 286 and 238 px of horizontal scroll appear. ## Research

- **WAI-ARIA APG "Window Splitter"** (fetched 2026-10-05, w3.org/WAI/ARIA/apg/patterns/windowsplitter): `role="separator"` focusable; `aria-valuenow`, `aria-valuemin/max` (typically 0-100); `aria-controls` the primary pane; `aria-label`/`aria-labelledby`. Keys: arrows move the splitter, `Enter` toggles collapse/restore of the primary pane, `Home/End` min/max (optional), `F6` cycles panes (optional). A fixed splitter omits arrows.
- **MDN `Element.setPointerCapture`** (fetched 2026-10-05): once set, later events for that pointer retarget to the capturing element even outside its bounds; capture auto-releases on `pointerup`/`pointercancel`; `lostpointercapture` fires on release; on touch, `touch-action: none` prevents the browser cancelling the drag.
- **Stylesheet tests** (`console/tests/test_stylesheet.py`):
  - `:65-84` `test_no_class_is_defined_twice_at_the_top_level`: a rule whose selector is exactly one bare class (`re.fullmatch(r"\.[A-Za-z][\w-]*", part)`, `:76`) may appear once, except `KNOWN_REPEATS = {".card"}` (`:26-30`). Compound or descendant selectors are exempt, so extend an existing bare rule in place or use `.lanes > .lane`-style refinements.
  - `:87-106` `test_the_hidden_attribute_is_honoured`: needs a `[hidden]` rule containing `display`, `none` and `!important`; exists at `styles.css:249`, so a handle can be hidden with the `hidden` attribute.
  - `:109-135` `test_every_class_the_js_styles_actually_exists`: every hyphenated class in a literal `class: "..."` string in any `static/*.js` (regex `class:\s*"([a-z][\w\s-]*)"`, `:127`) must appear as `.name` somewhere in `styles.css` (substring check, `:131`). Classes added with `classList.add` are not checked.
- **Script order** (`console/tests/test_plugins.py:231-240`): `palette.js` in the `<script src>` list; `index("palette.js") < index("app.js")`; `index("core.js") < index("palette.js")`; `assistant.js` present and before `app.js`. `splitter.js` can legally go in `index.html` directly after `core.js` (`index.html:46`) and before `desktop-chrome.js` (`:47`), 25 lines away from the uncommitted `onboarding-wizard.js` tag (`:72`). Static assets are globbed by the export (`console/server/export.py:87-90`) and served from the static dir (`httpd.py:25,94`), so no other registry needs a new file name.
- **Precedent in this codebase:** one-object-per-concern prefs and `section._setOpen`/`data-panel-id` (`core.js:254-298`); `matchMedia` `onchange` for breakpoint crossings (`agents.js:1501-1505`); drawer/Esc/focus contract (`app.js:14-53`).

## Recommended Path

Proposal for the requirements draft, not requirements. Build one small generic splitter helper (`console/static/splitter.js`, attached as `C.splitter`, plus one block of `.sp-*` CSS placed mid-file) that creates a focusable `role="separator"` handle, drags with Pointer Events and capture, writes the pane size as a CSS custom property on the pane's own container while dragging, commits one `layout` object to `C.prefs` only on release or after a keyboard step, clamps against the viewport and the sibling pane's minimum (re-clamping when the window resizes, without overwriting the stored value), and switches off at `<=900px` through a single shared media-query constant. Each surface then needs only CSS edits that consume a variable inside the existing rule plus one `attach` call: Agents list reuses the existing `chatListHidden`/`setListShown` state for its collapse (one fact, one place); the right rail attaches per chat or on `#agShell`; Vault attaches two handles on `.vault` and defers `resize()` until release; lane width sets `--lane-w` on `.lanes`. Treat the docked ticket panel as its own unit, because it changes page structure (a dock below the topbar, `main#view` shrinking, a mode switch back to modal across 900 px, in-place refresh) and its default depends on `T-037-questions.toml` Q1. Expandable sections reuse `C.panel` collapse with the ids in the context snapshot, a shared Collapse/Expand-all helper that lives in `splitter.js`, and a guard for N2. Reset layout is a `C.prefs.del("layout")` plus `panelOpen` clear behind one new Settings function. Suggested order for the planner: splitter helper + Agents, Vault, lane width, sections, Reset layout, then the dock.
