- Done: SIMPLIFY — one crash chased through three wrong diagnoses, recorded because the wrong turns are the useful part. The test binary died with an access violation, then heap corruption (0xC0000374), then an access violation again. I blamed WinRT apartment churn twice and restructured OCR accordingly — first a thread per call with paired `RoInitialize`/`RoUninitialize`, then a single long-lived worker thread with one apartment. Isolating by test filter found the truth: **two threads OPENING the system clipboard at once**, since `-- clipboard` matched both a clipboard test and an OCR test that deliberately touches COM first, and the whole suite passed single-threaded. The fix is a process-wide mutex in `clipboard.rs`, where the fact that there is one clipboard belongs. The single-worker OCR design was kept — it is the right shape for WinRT regardless — but its docstring no longer claims it fixed this.
