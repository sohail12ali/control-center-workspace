# Analysis: T-022

## Context

Give the 7 role agents and 39 skills a regression test: a stdlib-only golden-prompt eval runner (proposed home `console/evals/`) that grades behaviour. Scope is item 9 of [[INV-2026-10-01-paperclip-adoption-dossier]] (Tier 2); "golden-prompt evals" was also an undelivered Phase 5 item of [[INV-2026-08-29-control-center-v3-dossier]] (`...v3-dossier.md:151,241`). Reference is Paperclip's `evals/promptfoo` + `doc/evals.md:137-165`. Read-only survey; nothing built.

## Current State

How an agent turn is driven and observed here (verified by reading, not run):

- **Transport.** The `claude` row is `stream_json`: one process, stdin held open as a JSON-lines channel (`console/config/agents.toml:46,52-64`; `server/agent_backends.py:10-20,53-59`). `Backend.session_argv(mode, model, persona, ...)` builds the argv (`agent_backends.py:547-573`); persona becomes `--agent {persona}`, optional args vanish when empty (`:250-284`).
- **The one-shot form cannot be graded.** `oneshot_args` is `-p {prompt} --permission-mode --model` with no `--output-format` (`agents.toml:97-101`), so `kanban agents launch` captures plain text and no tool calls (`server/agents.py:164-177`, `:183-197`). A graded run must use `session_args` (stream-json).
- **Driving a turn.** `LiveSession.start` Popens the argv (`agent_session.py:404-425`); `_deliver` writes one `{"type":"user",...}` line (`:445-447`); closing stdin ends the process (`:476-492`). The prompt the Agents tab sends is `backend.compose_prompt(text, skill, persona, repo_root)` (`agent_manager.py:175-179`).
- **Observing.** Each stdout line goes through `Normalizer.feed` (`agent_session.py:255-278`) into the event vocabulary `session.init, text.*, tool.pending/start/result, usage, turn.end, notice, error, raw` (`agent_normalize.py:1-22`). `tool.start` carries `id`, `name`, parsed `args` (`:246-255`). `turn.end` carries `subtype`, `is_error`, `cost_usd`, tokens, `result` (`:313-323`).
- **Transcript format that already exists.** `console/.cache/agent-chats/{id}.events.jsonl` (normalized, `seq`-stamped, one JSON object per line) plus `{id}.log` (raw CLI lines, stderr interleaved) (`agent_manager.py:8-13,44-46`; `agent_session.py:629-648`). `agent_events.replay_file` parses it and skips a torn last line (`agent_events.py:60-79`). The directory is gitignored because transcripts can hold anything the agent read (`.gitignore:66`, `agent_manager.py:8-9`). Only ONE transcript exists on this machine (`fc9143d7696c`, 9 events) and it is a failed-auth turn (below).
- **Fixture transcripts in tests: none.** `grep` of `console/tests` for `Normalizer`, `agent_normalize`, `content_block_start`, `stream_event` finds nothing; the normalizer that every grader would sit on has no test. Existing tests use a throwaway `repo` fixture (`tests/conftest.py:120-130`) and per-module fakes.
- **Usage and cost.** Telemetry records a turn only when `cost_usd` is known; else `null` and the total is "partial" (`telemetry.py:16-27,134-137,237-246`). `price()` returns `(None,"unknown")` with no table row (`:89-111`); `console/config/pricing.toml` ships no rows. Side effects of a real session that an eval must not trigger: `notify.send` on every `turn.end` (`agent_session.py:308-326`) and a telemetry record (`:328-360`).
- **Lint.** `harness_lint.lint` checks frontmatter, dead `.claude/...` paths, orphan skills and CLAUDE.md roster counts ("7 agents . 39 skills" is warned on drift) (`harness_lint.py:246-317`). Baseline today: `39 skills, 7 agents | 0 error(s), 0 warning(s)`.
- **Verbs / CLI.** A verb is a `verbs.toml` row + handler `(repo_root, ticket=None, **args)` (`verbs.toml:21-23`); `needs_confirm` is a stray-call guard, explicitly "NOT the human approval gate" (`verbs.toml:25-30`; `verbs.py:140-149`). CLI subcommands register in `kanban.py:build_parser`, e.g. `harness lint` (`kanban.py:1015-1021`, handler `:341-353`). CI runs `python -m pytest -o addopts=""` on py3.11/3.13 plus `harness lint` (`.github/workflows/verify.yml`); local py is 3.14; 1416 tests collect today.
- **TOML subset (decides the scenario format).** `tomlio` supports tables, `[[arrays]]`, nested `[[a.b]]`, scalars, multi-line arrays; no inline tables, no multi-line strings, no single-quoted strings (`tomlio.py:1-13,19-24`). Probed: `[[scenario.check]]` nests correctly; a trailing `# comment` after a value is NOT stripped and silently corrupts the value (`a = "v" # c` parses to `"v" # c`); `\\.` is unescaped TOML-correctly and a bare `\.` is accepted leniently. Comments on their own line are skipped on read. It only loses comments on write, and scenarios are never written.
- **Role/skill rules that are testable** (all cited): `trace-context` first (`CLAUDE.md:56`, `skills/trace-context/SKILL.md:9`, `agents/analyst.md:14`, same step in every role); TOML never hand-edited (`CLAUDE.md:24`, `skills/questions/SKILL.md:19,46`); post-freeze change via `evolve` (`CLAUDE.md:56`, `skills/evolve/SKILL.md:8,28`); deployer ASK-gated (`agents/deployer.md:21`, `agents/harness.md:48`); commit/push/PR are ASK (`skills/do/SKILL.md:67`, `.claude/settings.json:4-6` `permissions.ask`); handoff refuses on a failed gate (`skills/handoff/SKILL.md:35`); a blocker carries impact/ETA and evidence (`skills/progress-tracker/SKILL.md:18`, `agents/verifier.md:22,45`); builder only with unchecked tasks (`agents/builder.md:3`); `do` exits clean with `ASK-GATE` when remote (`skills/do/SKILL.md:10`).

No live run was made for this analysis.

## Key Findings

- **F1 - Contradicts the v3 dossier: it asked for "judge-scored, run nightly by the scheduler"** (`v3-dossier.md:151`). Both halves are rejected here: an LLM judge adds a second unmeasured model, and a nightly paid run is unattended spend with no price table (`pricing.toml` empty) and an expired OAuth session. Significance: v1 is deterministic graders + opt-in live; the scheduler may later run the free replay verb, never live.
- **F2 - Normalizer drops `tool_result` for the claude backend.** `user` events become a `replay` notice (`agent_normalize.py:106-111`) and `tool_result` blocks are only read inside `assistant` messages (`:283-288`). Persisted Claude Code session logs put `tool_result` in `user` messages (checked against this session's own log structure, not a captured stream-json). Probed with synthetic input: the result was swallowed. Significance: v1 graders may only use tool CALLS, text and turn end, never tool results. Labelled inference; confirm against a real stream.
- **F3 - Possible duplicate `tool.start`.** With partial messages on, a `content_block_stop` yields `tool.start` and the later complete `assistant` message yields a second one with the same `id` (`agent_normalize.py:223-230` vs `:280-282`); synthetic input produced two. Whether the real CLI emits both is unconfirmed. Significance: tool calls MUST be de-duplicated by `id` in the eval view.
- **F4 - Usage collapses to zero in the normalized stream.** `turn.end` uses `or 0.0` / `or 0` (`agent_normalize.py:313-323`), so missing and real zero are indistinguishable. Telemetry already maps a falsy cost to `None` (`agent_session.py:353`). Significance: "UNKNOWN never zero" must read the RAW `result` event, so replay fixtures are raw stream-json lines (the wire format), run through the existing `Normalizer`.
- **F5 - `subtype:"success"` can carry `is_error:true`** (the only transcript). Disposition must key on `is_error` and `terminal_reason`, never `subtype`.
- **F6 - Claim rules are not in any prompt.** No role or skill tells an agent to `claim` before work or what to do on a conflict (`grep claim .claude/` finds only a stop-hook reminder, `.claude/hooks/console-stop-reminder.sh:3`; the verb exists, `verbs.toml:134-140`, `tickets.py:212-255`, and `setup_editor.py:30-44` only mentions it). The brief's "claim before work" / "stop on 409" therefore translate to the real rules above (trace-context first; stop on a refused gate), and a claim scenario is deferred until a prompt states the rule.
- **F7 - Live safety hinges on `plan` mode** (`agents.toml:103-104,142`, "read-only"). Headless Bash behaviour under `plan` is unverified; first live run must be one scenario. SessionStart hooks (`session-context.sh`) inject the real artifact-map into every live session, so live runs are not hermetic.
- **F8 - Sibling overlap.** T-020 item 1 (claude failure classifiers) overlaps the `infra` class; T-021 edits skill text and the `blocked` contract, which will trip scenario provenance quotes (intended gating). Both touch `kanban.py`.

## Research

Paperclip reference, read in full: `evals/promptfoo/tests/core.yaml` (six cases: pickup, progress, blocked, no-work exit, checkout-first, 409) grades free text with `contains`/`javascript` substring tests over a single-turn completion, run against 4 hosted models through OpenRouter (`promptfooconfig.yaml:19-35`), so it needs a paid key and tests what a model SAYS it would do. Several of its assertions pass on empty output (`not-contains` only). `doc/evals.md:137-165` supplies the taxonomy (product / model / grading / infrastructure; "missing usage or price data means unknown, not free"; zero-cost refresh from retained evidence) and `:205-275` the "freeze evidence, calibrate a grader against correct and plausible wrong evidence" loop, which this design makes mechanical with paired pass/fail fixtures.

## Recommended Path

Build `console/evals/` as a stdlib package: TOML scenarios (tomlio subset) with a closed set of five deterministic check kinds over the normalized stream (tool calls de-duplicated by id, text, turn end), raw-transcript fixtures with a golden-pass and a must-fail transcript per scenario, a `replay` mode wired into pytest (free, offline, proves the suite can fail) and an opt-in `live` mode (read-only `plan` mode, `--confirm`, refused under `CI`, usage UNKNOWN when unreported). CLI `kanban.py evals ...`; one read-only verb `evals-replay`, no live verb. Scenarios declare `subjects` (`agent:*`, `skill:*`, `core`) so `--changed` maps edited prompt files to the scenarios that gate them. Eight starter scenarios grounded in the cited rules, each with provenance quotes verified against the prompt files.
