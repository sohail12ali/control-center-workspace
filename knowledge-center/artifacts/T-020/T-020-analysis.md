# Analysis: T-020

## Context

T-020 ports the reliability half of the Paperclip adoption dossier (items 1-6) into the Delivery Console: classify failures, catch stalls, retry with caps, kill process trees, reap stale claims, cap review loops. Source: [[INV-2026-10-01-paperclip-adoption-dossier]] Tier 1. The dossier's premise ("no stall watchdog, retry, timeout or classification") rested on a grep of three files; this pass traced the paths. The premise is true but understates the gap: the Run store itself is write-once, so there is no lifecycle for a watchdog or retry to act on.

## Current State

- **A Run is created `running` and never updated.** `runs.set_state` has no caller outside `console/tests/test_runs.py:24` (grep over `console/`; callers of `runs_mod.` are `verb_handlers.py:220,335,396,405`, `assistant_feature.py:133`, `verbs_feature.py:95`). `STATES` already lists `needs-approval` and `interrupted` (`runs.py:17`) but nothing sets them. `console/.cache/runs/` is empty on this machine, so the claim rests on code reading, not on observed records.
- **Only two verbs create Runs**: `delegate` (`verb_handlers.py:220`) and `launch-role` (`verb_handlers.py:335`), both for `executor="chat"`. Chats started from the Agents tab create no Run. No code creates `job` or `cursor` executor Runs.
- **Sessions carry no timestamps for output.** `BaseSession._handle_line` (`agent_session.py:255`) never records when a line arrived; `Stream` stamps `seq`, not time (`agent_events.py:114`). Nothing can tell "silent for 20 minutes".
- **The reader blocks forever.** `LiveSession._read` and `TurnSession._read_turn` are `for line in proc.stdout` (`agent_session.py:498,576`): no timeout, no per-line cap. A process that emits a result and lingers (children holding the pipe) leaves `busy=True` and the queue undrained.
- **Kill is root-process only.** `LiveSession.stop` ends with `proc.kill()` (`:492`), `TurnSession.interrupt/stop` use `terminate()/kill()` (`:606,618,622`), `agents.stop_job` uses `terminate()` (`agents.py:339`). On Windows that is `TerminateProcess` on one pid; `cursor-agent` is `.cmd -> cmd -> powershell -> node` (memory `stray-terminal-root-cause`). No spawn site sets a process group on POSIX (`start_new_session`), so a POSIX `killpg` would hit the console's own group.
- **Env is inherited whole.** No spawn site passes `env=` (grep `env=` over `console/server`: none). This session's own environment carries 27 `CLAUDE*` variables, including `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_MESSAGING_TOKEN`. Paperclip's list of four names matches only two of them.
- **`turn.end` throws away the failure evidence.** `Normalizer._result` keeps `subtype`, `is_error`, `result[:4000]`, cost, tokens (`agent_normalize.py:313-323`); it drops `errors`, `api_error_status`, `stop_reason`. A real transcript on this machine shows `subtype:"success"` with `is_error:true` and `result:"Failed to authenticate: OAuth session expired and could not be refreshed"` (`console/.cache/agent-chats/fc9143d7696c.events.jsonl`), so `subtype` alone cannot classify.
- **A structured quota signal already exists.** `rate_limit_event` is normalised to a `notice` with `status`, `window`, `resets_at` (`agent_normalize.py:136-151`). Nothing consumes it.
- **Output caps exist only on the one-shot path** (`agents.py:57,183-189`: 200k chars, `truncated` flag, O(n^2) `sum(len)` per line). Live chats write every event and every raw line to disk with no cap (`agent_session.py:255-264`, `agent_events.py:130-136`).
- **Claims.** `set_claim` (`tickets.py:218`) is race-safe and refuses conflicts. `VaultBackend.claim` stamps `claimed_at` as `date.today().isoformat()` (`vault_backend.py:77`): a date, not a timestamp, so no TTL in hours is computable. `set_claim(..., claimed_at=None)` stores `""` (`tickets.py:251`; used by tests). `ready` skips any claimed ticket regardless of age (`vault_backend.py:65`). There is **no release verb**: `ready`/`claim`/`comment` only (`verbs.toml:128-148`); `claimed_by` is not in `EDITABLE` (`tickets.py:193`). No agent protocol or skill mentions `claim` (grep of `.claude/agents`, `.claude/skills`). `console context` does not show claim state (`context.py:195-222`).
- **`claimed_at` is read** by `stop_hook.py:61-69` (reminder to the claiming agent, string comparison against `updated` and `posted_on`). The dossier's "nothing reads `claimed_at`" is wrong; "nothing *expires* on it" is right.
- **Approvals** already bound a human wait: `approval_timeout` 300 s, deny on timeout (`agent_approvals.py:151-161`), and `approval.request`/`approval.decided` events land on the stream. This is the one existing timeout and the watchdog must not count it as silence.
- **Review loop.** `verifier.md` step 10 routes unmet criteria to the fixer with no counter and no cap; `fixer.md` has none either.

## Key Findings

- **Run lifecycle is the missing foundation.** Finding: nothing writes terminal state. Significance: every other item (liveness, retry, stale claim) reads Run state, so a Run-to-session reconciler comes first and is the largest unlisted piece of work.
- **Dossier item 5 contradicts Paperclip.** Finding: the dossier says adopt "if the owning run is dead *or* `claimed_at` is past a TTL". Paperclip adopts only when the owning run is terminal or missing, and states it "must not clear or adopt locks held by non-terminal runs" (`doc/execution-semantics.md:184`, `issues.ts:7505-7511`); there is no TTL. Significance: a literal TTL would steal claims from live long runs, and T-018 reuses one worktree per ticket, so two runs would collide. Design: never expire a claim with a live owner; TTL only when liveness is unknown.
- **Paperclip force-release is board-only** (`routes/issues.ts:15152`: agents get 403) and audited with previous lock ids. Significance: our verb has `needs_confirm` only, which is not a human gate (`verbs.toml:25-30`); the human gate is `gated_tools` in `agents.toml`, which tomlio would corrupt if written. Hand-edit by the user is the only safe path: non-blocking open item.
- **Paperclip has no Windows reference.** Finding: `detached: process.platform !== "win32"`, group id null on win32, direct-child kill only (`server-utils.ts:116-144,4744`). Significance: item 4's Windows half is original work. Reuse: `desktop/sidecar.py:208-245` already does `taskkill /PID /T /F` on nt and `killpg` on POSIX; the console package cannot import `desktop/`, so port into `console/server/procs.py`.
- **`taskkill /T` has a reach limit.** It walks live parent links; a grandchild whose parent already exited is unreachable. Job Objects (ctypes, stdlib) close that gap and also clean up on a server crash, but add a handle race and the breakaway failure class in memory `cross-platform-defects-only-ci-finds` (#5). Decision: `taskkill /T` now, Job Object deferred with a todo.
- **`zoneinfo` works here only because third-party `tzdata` is installed** (`zoneinfo.TZPATH == ()`, `import tzdata` succeeds). Significance: quota reset parsing of "resets 5pm (America/Chicago)" must fail closed when the zone is unresolvable.
- **`--max-turns` is not passed** in any `agents.toml` claude row (`agents.toml:52-103`). Significance: `error_max_turns` cannot occur on shipped config; classify it (cheap) but do not build machinery for it.
- **Default runs are read-only.** `default_mode = "plan"` for both CLI rows. Significance: Paperclip's `plan_only` class would flag every default run; the classifier must exempt read-only modes (Paperclip's `planExempt`, `run-liveness.ts:310`).
- **Paperclip's session handling conflicts with T-011.** It clears a poisoned/unknown session and starts fresh; this console's baseline refuses to resume silently as new (`agent_manager.py:282-285`). Do not port; classify those as non-retryable.
- **Adjacent defects found, out of scope**: (a) `tomlio._acquire_lock` leaves a crashed writer's `.lock` file blocking every later write for 5 s then `TimeoutError` (`tomlio.py:279-297`); (b) `agent_session._record_turn` and `_notify_turn_end` pass `self.cwd`, which is the worktree path for a ticketed Run, as repo root (`agent_session.py:321,342`), so telemetry for ticketed runs lands under the worktree; (c) baseline test rot below.
- **Baseline test state.** Touched-area modules: 222 passed, 3 failed (`test_stop_hook.py::TestStaleClaims::test_claim_with_no_update_is_stale`, `TestCliOneApi::test_json_reports_stale_claims`, `::test_plain_mode_prints_a_reminder_line`). Cause: fixtures hard-code `claimed_at="2026-09-16"` while `tickets.set_claim` stamps `updated` with the real `date.today()`, so any later day reads as "updated since claim". Pre-existing, not caused by this ticket. `harness lint`: 39 skills, 7 agents, 0 errors, 0 warnings.

## Recommended Path

Build in three slices, each shippable alone. **Slice A (foundation + hygiene):** Run lifecycle reconcile with new states, output timestamps, `procs` tree-kill + env strip + per-line/size caps, lingering-after-result kill. **Slice B (classify + watch + retry):** `turn.end` evidence, Claude classifier with quota reset parsing, liveness classes, stall watchdog thread, retry table. **Slice C (claims + review loop):** `claimed_at` as a UTC timestamp, stale-claim rule with `claim-release` and `claim-adopt` semantics through verbs, `review-round` counter with escalation, verifier/fixer protocol text. Paperclip rates the dossier items S to S-M; given the foundation work this is closer to L, about 2 weeks. UI is out of scope; no new skills or agents.
