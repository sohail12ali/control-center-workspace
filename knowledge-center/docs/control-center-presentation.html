Control Center Field Guide

One pipeline, seven agents, and a paper trail you can audit months later. The harness turns free-form asks into staged, gated, evidence-backed delivery — and the Delivery Console makes every ticket, tracker, and agent run visible on a local board.

Three parts

What it is

A project-independent workspace that sits next to your code. Nothing in it is coupled to a company, product, or stack.

The harness .claude/

Agent and skill definitions shared by Claude Code and Cursor. Every skill states only what to produce, in which layout, in which order — the model supplies the rest.

The vault knowledge-center/

An Obsidian vault. One directory per ticket, every artifact named {TICKET}-{artifact}.md, every file ending in a ## Links block so tickets render as connected clusters in the graph.

The console console/

A local web board + CLI — stdlib Python, vanilla JS, zero dependencies. It renders what the agents write, and it is the only writer of ticket and tracker TOML.

Six stages, seven agents

The fixer can be pulled in at any stage when something breaks: reproduce → root-cause → minimal patch → validating test. The harness agent orchestrates the whole line and never writes code itself. Deploying is always ASK-gated — a clean verify never ships anything on its own.

Don't want to name stages? /do "add a retry to the sync job" classifies the request into a lane, routes it through the same pipeline, and iterates until a defined DONE check passes.

Always on

The six gates, plus one rule that outranks them

GROUND

Never assume. Survey code and prior artifacts before drafting anything.

CLARIFY

Ask every open question before producing output. Critical questions block the freeze.

CANONICAL

Every fact lives in exactly one file. Search before creating; link instead of copying.

TEMPLATE

Every file type derives from a template in _template/. No template, no file.

SIMPLIFY

The minimum that works. No speculative abstraction, no extra indirection.

VERIFY

Every "done" claim carries cited evidence — build, test, file:line.

BE HONEST

Failures reported with output, skips named, uncertainty labeled. Bad news early. This rule crosses every stage.

The unit of work

A ticket, end to end

The requirements pipeline is one skill with five ops — requirements draft | enrich | iterate | freeze | stories — with challenge-requirements red-teaming the draft between passes (gaps, contradictions, untestable criteria, and overlap with existing features).

Pipeline events move the card: kickoff creates it in open, the first build task moves it to in-progress, close-work lands it in done. The board never drifts from the artifacts because both are written by the same CLI.

Boards

Tickets and Investigations ship on; Migrations and Releases are config-present, off by default. Lanes, WIP limits, and tones are TOML.

Overview · Analytics · Work

Attention buckets, lane funnel, throughput and ageing charts (every chart has a table twin), and a timesheet read straight from the daily logs.

Todos · Vault · Settings

Every todo across every ticket; the vault's wikilink graph; per-browser prefs — five themes with four-colour sampled swatches, tab visibility, voice.

Humans in the loop

Agent chats — launch, steer, approve

The Agents tab runs a real CLI as a live session: pick a backend, a permission mode, a persona, a skill, and a model — a curated shortlist (aliases like opus, pinned ids like claude-fable-5) plus a custom-id box for anything else. Messages steer mid-turn; interrupt stops a turn without killing the session.

The approval gate. Gated tools — Bash, file writes, WebFetch, subagents, plan exits — are held by a PreToolUse hook until you answer in the chat. Silence denies, fail-closed, after 300 seconds.

CLI ──spawns──▶ hook ──POST──▶ console ──SSE──▶ browser ▲ │ └────── verdict ◀── POST ──────┘

Voice. Read-aloud speaks each finished reply (off by default). Announce — on by default — says "The agent is done." at turn end and "Permission needed for Bash" when a run parks on you, so a blocked run is never silent.

Getting started

Three steps

  • Add your project as a sibling folder and list it in control-center-workspace.code-workspace. Tickets reference your code by path; the harness never moves it.
  • Serve the console — python console/kanban.py serve — and open the vault in Obsidian if you like graphs with your Markdown.
  • Start work: /kickoff T001 "…" for a scoped ticket, /ticket-draft when you're not sure it deserves one, /investigate when you're not sure it's even a bug, or /do "…" to let the dispatcher decide.

Everything an agent claims is backed by an artifact; everything on the board is backed by TOML the CLI wrote; everything you approved is on the record. That's the whole idea.
